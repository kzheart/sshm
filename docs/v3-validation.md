# sshm 0.3.0：连接复用验证

日期：2026-09-14。本地 macOS arm64，隔离 Linux sshd；真实测试仅 macmini 与 tencent。真实性能测试阶段配置与 known_hosts 前后哈希一致；安装阶段的后续核对见文末说明。报告不包含地址或凭据。

## 实现范围

`exec` 自动复用同一个用户的短期服务，每个配置路径与别名共享一条 SSH 连接，每次执行建立独立通道。仍是 Go 单二进制，无 OpenSSH、Node、Python 运行时依赖。CLI stdout/stderr 保持原始文本或字节流；内部 Unix socket 传递请求与文件描述符，不要求 Agent 消费 JSON。

不新增用户需要管理的 session 工具。增加 `--fresh` 强制独立连接，`--debug` 显示是否复用。shell/copy 沿用独立连接；本次不让它们共享底层传输。

文件锁跨整个服务生命周期持有，解决并发启动与崩溃后的旧 socket。默认每用户一个服务；显式不同 `SSHM_RUNTIME_DIR` 用于隔离测试，会各自创建服务。连接空闲 60 秒回收；服务无任务后空闲约 60 秒退出。缓存上限 32、每连接执行并发 8、服务同时请求上限 64。

配置、私钥与可信公钥内容每次重新检查；变化后重新认证。取消/输出故障停止复用该连接，允许已有其他任务完成，之后关闭传输。网络失效探测间隔 10 秒、响应期限 5 秒。执行请求失去确认或状态不明时不自动重放。

## 重复执行延迟

全部使用同一 0.3.0 二进制执行短命令 `true`，`--fresh` 与默认复用交错测量，统计 CLI 全进程耗时。复用样本逐次检查 `reused=true`；不把首次调用混入复用统计。

| 环境 | 每种模式样本数 | 新连接中位数 | 复用中位数 | 中位耗时减少 | 新连接/复用 p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 本地隔离 sshd | 30 | 52.166 ms | 12.376 ms | 76.3% | 63.665 / 22.102 ms |
| macmini | 15 | 641.302 ms | 78.867 ms | 87.7% | 890.630 / 111.334 ms |
| tencent | 15 | 700.432 ms | 138.224 ms | 80.3% | 815.925 / 222.947 ms |

真实机器每台另通过 16 次、4 并发调用，以及超时后重新连接。真实测试仅执行 true/sleep，没有修改远端业务文件。初始调用单独记录为 `initial_call_ms`：它可能已经有连接，不能一律解释为冷启动。

这组数据说明持续操作期间省掉握手的收益；不表示首次连接或远端命令本身会同样加速。样本有限，特别是 15 次样本的 p95 接近最大值，受网络波动影响。

原始数据：[本地](reuse-results.json)、[真实服务器](reuse-live-results.json)。

## 并发、资源与故障

- 32 个 CLI 同时首次启动：全部成功，只有 1 个服务。
- 1,000 次真实跨进程调用、16 并发：0 失败，2.072 秒；服务 FD 9 → 9，RSS 18,300,928 → 19,447,808 字节。
- 100 次长命令超时、8 并发：全部返回 124，服务 FD 回到 8；远端 sleep 使用隔离容器，容器在结束时删除。
- 同进程 Go 竞态测试：1,000 次调用、16 个 worker、实际只有 1 条连接；关闭池后连接 0、FD 6 → 6、goroutine 3 → 3，GC 后堆 376,512 → 650,296 字节。[原始数据](reuse-pool-soak.json)
- SIGKILL 调用端：复制到服务的输出管道及时释放，同连接其他任务成功完成。
- SIGKILL 服务：执行中命令报告 125；下一次调用重建服务，旧 socket 不阻塞启动。用隔离远端文件计数核实只执行 1 次，没有重放。
- 真正静默断网：暂停隔离容器；即使 CLI 使用 `--timeout 0`，连接存活探测仍在 14.990 秒后返回 125。恢复网络后成功重连。
- stdout/stderr 消费方关闭或停止读取、stdin 保持打开、总期限及 SIGTERM 均有覆盖；诊断本身的 stderr 写入也有期限。
- 配置密码改变、私钥权限改变、known_hosts 删除可信 key 均拒绝沿用旧认证；有效配置恢复后重新连接。
- 100 次错误本地协议请求：FD 保持 9；Linux 容器内确认 `reused=true`，没有用独立连接回退掩盖问题。
- 真实 60 秒空闲期限：60.53 秒后服务数 0、socket 删除。无需测试专用缩短期限。

[故障补测原始数据](reuse-fault-results.json)。这些结果没有发现持续增长的 FD、goroutine 或后台服务残留；不是对所有环境的无限时长泄漏保证。

## 吞吐与代价

复用连接、输出到 `/dev/null`、每项 3 次：1 MiB 中位 10.440 ms（95.78 MiB/s）；32 MiB 中位 44.456 ms（719.81 MiB/s）。是本地端到端结果，不能推算成公网吞吐；本轮主要目标是重复调用延迟。

运行期间增加一个短期 Go 服务，测试中约 17–19 MiB RSS，另有前台 CLI 自身开销。取消命令会让这条连接退出缓存；已有其他命令完成后释放，所以取消后下一次调用可能重新握手。共享底层 TCP 真正失效时，同连接的命令都会受到影响。服务器端撤销凭据不会让既有 SSH 认证自动失效，需要马上重新认证可用 `--fresh`。

## 回归与复现

Go 竞态测试、vet、格式检查通过；原有 23 组隔离真实 sshd 集成测试通过，包含 PTY、SFTP、跳板、二进制输入输出、Linux、加密私钥等。新增连接池用例覆盖复用、凭据与信任更新、取消隔离、空闲回收、通道排队及缓存上限。

```sh
make check build
python3 tests/integration.py
python3 tests/reuse.py
python3 tests/reuse_faults.py
python3 tests/reuse.py --live macmini tencent --report docs/reuse-live-results.json
make dist
python3 tests/install.py
```

发布包仍为 macOS/Linux × arm64/amd64，安装不需要注册系统服务或发布公共仓库。升级备份位于本机 `~/.local/state/sshm/upgrade-0.3.0-*`，可用其中旧二进制与 Skill 回退。首次性能测试发现 channel-close 不能视为远端确认，已补充取消后停止复用并回收连接、释放输出 FD；补测静默断网和阻塞 stderr 后再安装。

安装验证：已安装二进制与源码构建产物一致，共享 Skill 与源码一致，Claude Skill 链接仍指向共享目录。已安装版本在 PATH=/nonexistent 下对两台服务器分别确认首次连接及 reused=true。

安装最终核对发现 `sshm.toml` 与备份一致，但 `known_hosts` 的哈希与安装前备份不同，变化来源未确定。本次 CLI 与安装器无写入该文件的逻辑；没有覆盖当前文件。随后用已安装版本分别对两台强制重新认证成功，该轮验证前后 known_hosts 哈希一致。期间还回收了旧客户端会话重新拉起的一份旧 SSH MCP 进程，三个客户端的旧配置入口仍不存在。
