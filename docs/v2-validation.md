# sshm 0.2.0 验证与性能报告

日期：2026-09-14。运行环境为本机 macOS arm64；隔离服务器为 Docker 内 Linux OpenSSH，真实目标仅为用户授权的 macmini（macOS）与 tencent（Linux）。测试使用现有可信公钥，没有更改服务器认证配置或业务文件。

## 最终实现与安装

- SSH 内置 `golang.org/x/crypto/ssh v0.57.0`，SFTP 使用 `github.com/pkg/sftp v1.13.11`，TOML 使用 `github.com/pelletier/go-toml/v2 v2.4.3`，终端使用 `golang.org/x/term v0.46.0`。
- 每次调用独立连接，结束关闭整个跳板链；没有后台连接池、控制 socket 或外部 SSH 子进程。
- 保留 hosts / exec / doctor，增加内置 shell 与单文件 copy，替代以前依赖原生 ssh/scp 的入口。
- 配置统一为 `~/.ssh/sshm.toml`，内容与迁移前逐字节一致。`known_hosts` 保留为可信公钥记录。
- 已安装 `~/.local/bin/sshm` 0.2.0，更新 Codex / Cursor 共用的 `~/.agents/skills/sshm`；Claude Code 的原有符号链接继续指向同一份 Skill。
- 移除旧版生成的 `~/.ssh/sshm.conf`、其 Include、Python askpass 和旧 Skill 的本机说明。用户原有 SSH 配置内容保留。备份位于 `~/.local/state/sshm/upgrade-0.2.0-ornanbcu`。

## 正确性与资源回收

14 组 Go 测试（含 race）和 go vet 通过。覆盖原始命令/退出码、二进制 stdin、默认 EOF、上游保持 stdin 打开、输出截断后的排空、输出写入失败、下游不读取、握手卡住、执行请求不确认、缺失退出状态、主机公钥拒绝、凭据拒绝、配置错误不泄露密码、并发取消隔离、资源注册与关闭竞争，以及特殊文件拒绝。

23 组隔离真实 SSH 集成测试通过，另覆盖密码、密钥、加密私钥、混合认证的跳板链、32 个并发独立调用、真实 PTY 问答与尺寸、终端取消后的模式恢复、SFTP 往返与禁止覆盖、正在传输时取消、Linux 二进制及清空 PATH 后的运行。最后补测 shell 上游关闭 stdin 和下游关闭输出两种情况，CLI 均及时退出；交互调用不再仅发送半关闭后一直等待远端。

1000 次调用的进程内压力测试使用 8 个并发 worker，其中每十次有一次执行请求故意不确认并触发取消。最终记录：

| 指标 | 之前 | 之后 |
| --- | --- | --- |
| 文件描述符 | 5 | 5 |
| goroutine | 3 | 3 |
| GC 后 heap | 404016 字节 | 753824 字节 |

失败 0 次，最终服务端活动连接 0。这是进程内循环，可以观察被进程退出掩盖的资源残留；本次未发现文件描述符或 goroutine 持续增长。原始记录见 [连接压力数据](performance-soak.json)。

另有 100 个独立 CLI 进程的超时压力测试，8 并发，全部返回预期 124；100 ms 期限的端到端 p50 为 124 ms，包含取消与回收时间。实际 SFTP 中断测试使用 2 GiB 稀疏源文件，传输途中在 1 秒期限取消，检查远端文件已经写入部分内容且小于完整大小，然后删除隔离测试文件。

终端测试初次发现 macOS 的 PENDIN 位会由内核改变。核对其语义后，测试排除这个瞬时输入状态位，继续严格比较实际终端模式；不是通过忽略 raw/canonical 模式差异让测试通过。

## 本地性能对照

同一个隔离 sshd、同一私钥、同一主机公钥。延迟测试按方法交错运行，各 30 次；表中为 p50。旧版复用连接预先建立，因此应与首次连接区别解释。

| 场景 | p50 |
| --- | --- |
| 新 Go CLI，独立连接 | 50.262 ms |
| 原生 OpenSSH，独立连接 | 49.235 ms |
| 旧 CLI 0.1.1，禁用复用 | 65.443 ms |
| 旧 CLI 0.1.1，已有复用连接 | 35.203 ms |

新实现首次调用开销接近原生 OpenSSH，低于旧 CLI 的独立连接调用；它不提供旧版已有连接的跨进程复用性能。测试中将 20 个确定步骤合并到一次命令，耗时从 713 ms 降到 49 ms。因此保留单进程生命周期，优先通过一次脚本完成相关步骤，不增加后台服务。

吞吐测试输出丢弃到 `/dev/null`，包含启动、认证和传输，不是纯链路带宽，也不是磁盘写入速度；每项 3 次，以中位耗时计算：

| 输出量 | 新 Go CLI | 原生 OpenSSH |
| --- | --- | --- |
| 1 MiB | 22.35 MiB/s | 13.99 MiB/s |
| 32 MiB | 437.95 MiB/s | 330.39 MiB/s |

第一轮发现 `/dev/null` 被当成可能阻塞的终端，每 512 字节做一次 poll + write。改为整块写入这个不会产生背压的设备，保留管道/终端的取消处理后，32 MiB 测量从约 228 MiB/s 提升至约 438 MiB/s。其他环境因素也会影响前后结果，不能把全部差异当作稳定收益。[优化前数据](performance-local-before-output-fix.json)、[优化后完整数据](performance-local.json)。

每档 64 次独立调用的并发压力结果：

| 并发 | 调用/秒 | 失败 |
| --- | --- | --- |
| 1 | 22.23 | 0 |
| 4 | 108.64 | 0 |
| 16 | 297.2 | 0 |
| 32 | 310.41 | 0 |

隔离 sshd 的 MaxStartups 设为 64，以验证客户端并发能力；这不代表生产服务器允许相同并发。真实服务器只做了 4 并发。

## 内存随输出量的变化

每档三次新进程，使用 macOS `/usr/bin/time -l` 的最大 resident set size；数据不在 Python 中收集或缓存：

| 输出量 | CLI 峰值 RSS 范围 |
| --- | --- |
| 1 MiB | 12.88–13.20 MiB |
| 64 MiB | 17.36–18.05 MiB |
| 256 MiB | 17.47–18.25 MiB |

输出量从 64 MiB 到 256 MiB，内存峰值没有按数据量增长。Go 运行时本身有成本：64 MiB 单次对照中 Go 约 17.6 MiB，原生 OpenSSH 约 4.6 MiB；不能宣称内存优于 OpenSSH。[内存及 CPU 原始数据](performance-memory.json)。

## 真实服务器验证

24 个实机测试分组全部通过，包含认证、临时目录、退出码与双输出、二进制输入、脚本、1 MiB 输出截断排空、4 并发、超时与兄弟调用、SFTP 往返/拒绝覆盖、交互 PTY、基线测量和清理。临时目录均按本次标记确认后删除，TOML 与 known_hosts 内容校验保持不变。[实机完整结果](live-v2-results.json)。

随后另做性能重复采样：短命令各 10 次，64 KiB 和 1 MiB 输出各 5 次，输出方法交错并交换先后顺序。下表为中位数：

| 目标 | 短命令 Go / OpenSSH | 1 MiB 输出 Go / OpenSSH |
| --- | --- | --- |
| macmini | 520.9 / 596.2 ms | 719.6 / 1040.4 ms |
| tencent | 848.1 / 843.6 ms | 1489.2 / 1575.0 ms |

本次真实网络的短命令表现总体接近 OpenSSH，不能宣称所有网络上都更快。第一次单样本测量中 Mac mini 的 Go 传输曾更慢；重复采样体现了网络波动。腾讯云此次链路也明显不同于 0.1.1 验证时的低吞吐状态，不能拿那次约 49 秒直接对比并归因于更换库。[实机重复采样数据](live-v2-performance.json)。

## 发布与边界

四份发布包、校验和、重复安装和含空格路径的安装测试通过。安装后的二进制清空 PATH，仍成功登录 Mac mini / 腾讯云，证明运行不依赖外部 ssh 或 Python。Codex 实际发现一份启用的新版 Skill；Cursor / Claude Code 共用的发现目录保持有效。

这些测试验证了当前场景中的本地资源回收，不保证本地取消会杀死远端整个进程树。没有跨调用连接复用；文件传输失败可能保留部分目标文件。远端 Windows、BSD、网络设备、多因素登录和硬件密钥尚未实测或实现，不宣称完整替代 OpenSSH 的所有能力。

复现入口：`make check`、`make integration`、`python3 tests/performance.py`、`python3 tests/memory.py`。实机测试需明确指定已获授权的 `--hosts`；单独性能重测用 `tests/live.py --performance-only --hosts ...`。
